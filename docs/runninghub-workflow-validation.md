# RunningHub 工作流覆盖校验

本修复仅改变插件的请求准备流程，不包含任何个人工作流、模型选择、提示词或 API Key。

## 使用

更新插件并刷新页面后，旧预设默认继续只发送占位符替换值和运行时变化的输入。

RunningHub 设置顶部新增「发送本地工作流中的固定参数（图片与视频共用）」，默认关闭。
只有需要把本地模板中的固定模型、LoRA 权重等覆盖到云端时才开启。开启后要求本地模板与目标云端工作流的节点、类型、字段和连线匹配。不需要在 JSON 中添加隐藏元数据。

每次创建任务前，插件使用本次任务实际租用的 API Key 和 Workflow ID，读取云端的 API 格式 JSON，再校验所有准备发送的覆盖项。队列重试换 Key 时重新校验，不使用跨账号或过期缓存。新增校验逻辑不记录密钥或完整服务端错误响应。

## 边界与兼容性

- 默认模式不会把旧预设中未变化的静态节点突然变成覆盖项。云端不存在的静态节点不属于默认模式的发送范围。这不代表这些节点在云端生效。
- 对于准备发送的任何字段，无论是不是占位符，都必须在云端找到同编号、同类型的节点和对应输入。无法匹配时在创建任务前停止，不猜测映射、不更改节点编号、不删除失败字段重试。
- 固定参数模式不会忽略缺失的模型或 LoRA 节点；也不支持改变连线或创建节点。需要增加节点或调整连线时，先在 RunningHub 中编辑、保存，再从同一个工作流导出 API JSON。
- 固定模式下，即使本地种子与云端默认值相同，也显式发送 `seed` / `noise_seed`，避免服务端自动重新随机。其他不变静态默认值无需重复覆盖。
- 此模式只覆盖输入，不会把本地的节点 mode、界面位置等编辑器属性同步到云端。
- 读取云端 JSON 失败、无访问权限、响应异常或超过 20 秒时停止，不降级为未经校验的调用。取消任务会终止校验并释放本次租用的 Key。
- 这会增加一次云端 JSON 读取请求。该端点不可访问的环境将得到明确的预检错误；不能只凭生成端点可用就假定 JSON 端点也可用。
- 云端节点在校验与创建之间仍可能被外部修改。服务端的最终校验错误会原样交给现有错误处理，不自动重试或生成另一套参数。
- 错误信息中的「未创建生图任务」只描述该次校验失败的尝试。更早的独立任务不在此范围内。

## 测试

```sh
node --input-type=module --check < index.js
node --test tests/runninghub-workflow.test.mjs tests/runninghub-integration.test.mjs
```

测试包含纯逻辑、网络错误、读取超时、取消、Key 隔离、设置开关，以及从实际发布的 `index.js` 提取的图片、参考视频、视频直连测试三个入口的提交及 finally 清理流程，以及图片/参考视频的队列重试。测试使用虚构节点和模拟网络，不调用收费生成接口，也不证明任意账号中的模型可用或出图画风正确。

## 官方接口依据

- 获取真实 API 格式工作流：`POST https://www.runninghub.ai/api/openapi/getJsonApiFormat`，请求中使用 `apiKey` 与 `workflowId`，读取返回值 `data.prompt`。
- 节点覆盖只修改已有工作流的输入，不创建本地新增节点。
- 官方国际站接口文档：https://www.runninghub.cn/runninghub-api-doc-en/api-425761094
- 节点覆盖及种子说明：https://rhtv.runninghub.cn/runninghub-api-doc-cn/doc-8287336
- 覆盖项说明：https://rhtv.runninghub.cn/runninghub-api-doc-cn/api-425749013
